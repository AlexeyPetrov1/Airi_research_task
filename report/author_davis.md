# Первый эксперимент: DAVIS `bmx-trees`

**Статус: PASS.** 30 будущих шагов для всех 8 точек действительно сгенерированы установленной моделью MolmoMotion, проверены по исходному текстовому ответу и сопоставлены с отдельной официальной разметкой PointMotionBench. Это анализ одного эпизода, а не воспроизведение агрегированных чисел статьи.

## Данные и протокол

- Эпизод: `davis_bench / bmx-trees / bike_rider`; авторский пример `examples/data/davis_bmx_trees`.
- История: исходные кадры DAVIS `0, 1, 2`; `t₀=2`; восемь индексов точек `9, 12, 17, 18, 27, 29, 32, 34`.
- Прогноз и эталон: кадры `3..32`, ровно 30 последовательных шагов. [Карточка PointMotionBench](https://huggingface.co/datasets/allenai/PointMotionBench) указывает для DAVIS **24 кадра/с**; конечный шаг расположен на `30/24 = 1,25 с` после `t₀`. Произвольная частота кадров не назначалась. Это временной протокол авторского примера, а не стандартный 15 fps протокол сводной таблицы статьи.
- Источник RGB: [официальный архив DAVIS 2017 TrainVal 480p](https://davischallenge.org/davis2017/code.html), файл `DAVIS-2017-trainval-480p.zip`, только извлечённые `bmx-trees/00000.jpg..00032.jpg`. SHA-256 архива записан в `provenance.json`. Встроенные три JPEG слегка повторно закодированы: средняя абсолютная разность пикселей с исходными 2,61–2,82/255.
- Независимый эталон: `allenai/PointMotionBench`, ревизия `564ffa2e3cdb0ba443db8590b40e9691f487436c`, файлы `davis/tracks/bmx-trees_{2d,3d}.npz`. Официальные треки имеют 80 кадров, 2D видимость и 3D координаты. Входные 2D точки при `t₀` и весь 3D исторический тензор **точно совпали** с выбранными строками официальной разметки; это проверено `np.array_equal`. Будущие координаты не использовались для входа, выбора инструкции или настройки модели.
- 3D эталон — восстановленные и проверенные авторами траектории в метрах, **не прямое физическое измерение**. Документация [конвейера авторов](https://github.com/allenai/molmo-motion/blob/main/data_generation/README.md) описывает оценку глубины и позы камеры, 2D отслеживание, подъём в 3D и сглаживание. Конкретные опубликованные 3D массивы PointMotionBench использованы как эталон; точность реконструкции отдельно здесь не измерялась.

Модель получила только три исторических изображения, 2D координаты точек в `t₀`, три исторических 3D положения и авторскую подпись `A BMX rider rides through the trees`. Для F=30 сохранён точный выход процессора в `processor_inputs.pt`. Прогноз `future_3d` имеет форму `(8, 30, 3)` и конечные значения во всех 240 ячейках. Сырой ответ `model_output_raw.txt` содержит разбираемый блок `<tracks>`; независимая проверка `tracks_to_array` подтвердила 240/240 позиций, поэтому нулевая заглушка API и техническое заполнение неполного ответа исключены. Официальный путь вызова — `MolmoMotion.predict_trajectory(**inputs)`.

## Метрики

Все три метода сравнивались на одинаковых точках, шагах и маске: 215/240 допустимых пар «точка–кадр» (89,6%). `ADE = mean ||prediction - reference||₂` по этим парам; `FDE` — средняя ошибка только на **фиксированном шаге 30**, без подмены последним видимым шагом каждой точки. На шаге 30 эталон доступен для 8/8 точек. Шаг 15 полностью скрыт маской, поэтому график имеет разрыв; отсутствующие значения не приравнивались к нулю.

Статическая база повторяет 3D положение в `t₀`. База постоянной скорости использует разность 3D положений в кадрах 1 и 2 и умножает её на число будущих интервалов по `1/24 с`.

| Метод | ADE, м ↓ | FDE на шаге 30, м ↓ | Покрытие |
|---|---:|---:|---:|
| MolmoMotion | **0,376** | **0,724** | 215/240; FDE 8/8 |
| Неподвижность | 1,949 | 3,707 | 215/240; FDE 8/8 |
| Постоянная скорость | 0,573 | 1,089 | 215/240; FDE 8/8 |

Точные числа, покадровые ошибки и покрытие: [`metrics.json`](../runs/author_davis_bmx_trees_f30/metrics.json), [`metrics.csv`](../runs/author_davis_bmx_trees_f30/metrics.csv). Проверены искусственные случаи нулевой ошибки, известного смещения, равномерного движения, частичной и пустой маски, NaN и неполного прогноза: `synthetic metric checks: PASS`.

## Визуальная проверка и ограничение координат

Прогноз и 3D эталон живут в **фиксированной 3D системе камеры `t₀`**. Их общая проекция через сохранённую матрицу `K` показана на фоне кадра `t₀`; справа от изображения видны координаты вне исходного поля зрения. Красный — прогноз, зелёный — 3D эталон там, где он валиден.

![Прогноз и 3D эталон в системе t0](../runs/author_davis_bmx_trees_f30/trajectory_comparison.png)

На реальных будущих кадрах зелёным показаны **исходные 2D треки** и их видимость. Изображения проверены вручную: номера кадров, движение велосипедиста, подписи и точки согласованы. Файлы: [`наблюдение и будущее`](../runs/author_davis_bmx_trees_f30/observed_and_future.png) и [`реальное продолжение MP4`](../runs/author_davis_bmx_trees_f30/real_continuation_gt.mp4).

![Наблюдаемые и будущие кадры](../runs/author_davis_bmx_trees_f30/observed_and_future.png)

Проекция фиксированных 3D координат на движущиеся будущие кадры **некорректна без покадровых внешних параметров камеры**. Это подтверждается прямой проверкой: 3D эталон, спроецированный только через `K`, отличается от опубликованных будущих 2D треков в среднем на 448 пикселей, к концу — примерно на 839 пикселей. В доступных файлах есть `K` при `t₀`, но нет покадровых поз для обратного переноса в каждый будущий кадр. Поэтому прогноз не наложен на реальное видео как будто он в координатах каждого кадра. Это ограничение визуализации, а не расчёта 3D ADE/FDE.

- Checkpoint: `MolmoMotion-4B-H3-F30`, ревизия Hugging Face `3f5e790a511ff2cdf21c8d2a14cb4d8409c94629`; `config.yaml` SHA-256 `7e518af747f12fec9e1a249209380330207adf11aad8475a7362671b6ff912a0`; `model.pt` 17 847 894 425 байт.
- WSL Ubuntu, Python 3.11.16, PyTorch `2.9.1+cu128`, RTX 4070 12 ГБ. Полный запуск: **298,53 с**, пиковая выделенная CUDA память **9,74 ГиБ**, резерв CUDA **10,59 ГиБ**, пиковый RSS процесса **22,48 ГиБ** (включая загрузку весов на CPU). Максимальный бюджет генерации по умолчанию `160 × 30 = 4800` токенов, фактический ответ 4112 символов. Журнал этапов: [`run_status.json`](../runs/author_davis_bmx_trees_f30/run_status.json).

Точные команды из PowerShell в `F:\AIRI_task\molmo-motion` (установленные окружение и checkpoint уже описаны в `README_SETUP.md`):

```powershell
$rev = '564ffa2e3cdb0ba443db8590b40e9691f487436c'
$dest = 'data\pointmotionbench\davis'
New-Item -ItemType Directory -Force -Path $dest | Out-Null
foreach ($name in @('bmx-trees_2d.npz', 'bmx-trees_3d.npz')) {
    curl.exe -L --fail -o (Join-Path $dest $name) "https://huggingface.co/datasets/allenai/PointMotionBench/resolve/$rev/davis/tracks/$name"
}
curl.exe -L --fail -o (Join-Path $dest 'DAVIS-2017-trainval-480p.zip') 'https://data.vision.ee.ethz.ch/csergi/share/davis/DAVIS-2017-trainval-480p.zip'
wsl -d Ubuntu -- /mnt/f/AIRI_task/.venv/bin/python /mnt/f/AIRI_task/molmo-motion/scripts/prepare_author_davis.py
wsl -d Ubuntu -- bash -lc 'cd /mnt/f/AIRI_task/molmo-motion && /mnt/f/AIRI_task/.venv/bin/python scripts/run_author_davis.py'
wsl -d Ubuntu -- /mnt/f/AIRI_task/.venv/bin/python /mnt/f/AIRI_task/molmo-motion/scripts/evaluate_author_davis.py
```

Официальный DAVIS распространяет исходные кадры единым архивом около 833 МБ; подготовка извлекает только 33 кадра нужного эпизода. Повторный расчёт метрик и рисунков требует только файлов в [`runs/author_davis_bmx_trees_f30`](../runs/author_davis_bmx_trees_f30) и **не загружает модель**. Запуск F=1 находится в другой папке и не перезаписывался.

Ограничения интерпретации: один эпизод и восемь точек не дают оценки среднего качества на DAVIS; 3D эталон зависит от восстановления геометрии; покадровая 3D проекция на реальные RGB кадры без поз камеры невозможна.
