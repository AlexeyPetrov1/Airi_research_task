# FMB moving-wrist controlled geometry experiment

Goal source: attachment `866d697f-4a85-44dd-9495-4d34819fd17d/pasted-text-1.txt`, plus the user's three instructions: choose a suitable episode, use official wrist intrinsics, and use a VLM to assess trajectories.

The experiment preserves FMB v1 and v2. Its principal scene is the independently source-matched ShareRobot episode 5201, raw `1_M_L_3_vertical_n_2.npy`, with t0=126. The observed prefix is frames 77–126 (50 distinct frames, nominal 10 Hz); MolmoMotion sees only 124–126. Future 127–146 is withheld until prediction inputs, geometry choice, and model calls are sealed. Deserializing the trusted NPY dictionary materializes the source record; no future pixels, depths, or poses enter selection or reconstruction.

Episode suitability is judged from observed pixels and robot motion: visible target, mask area, valid depth, static background texture, multi-axis robot rotation, and sufficient remaining recording length. Unusual object count is not a selection criterion. The ten local candidates are audited in `selection/candidates.json`; episode 5201 also preserves comparability with prior studies. A low-texture red peg and limited secondary-axis motion are explicit limitations, not proof of suitability for every method. If its geometric gate fails, document that failure and evaluate an independently observed-selected control without silently changing the primary.

Official calibration and capture code are pinned in `sources/source_receipts.json`. Official wrist assets are the starting calibration prior. A factory rectified profile must be linked to the actual RGB camera and crop/resize; published factory parameters alone do not prove effective RGB K256, depth units, recording serial, or hand-eye X. Invalid profile entries are excluded by bounds and focal checks. Candidate pixel transformations are judged on observed static correspondences and held-out frames, never future ADE.

Required work:

1. ViPE default author pipeline on wrist_2 observed 10 Hz video; no repeated/resampled 15 Hz frames. Save exact frame IDs, pose conventions, K, depth, versions, run and resource receipts. A documented no_vda control is allowed if the author default fails; it cannot be labeled an exact default replication.
2. Compare K_official, K_ViPE, K_UniDepth on the same image coordinates. Validate crop/profile hypotheses on static observed background and RGB-depth boundaries.
   Aspect control: the pinned capture code resizes 640x480 to square 256x256. Canonical ViPE estimates equal fx/fy on that distorted square. Restore RGB to 256x192 before a second unchanged default ViPE run, keep the original 256x256 run, and explicitly map resulting K/depth back to model image coordinates. There is no temporal resampling and MolmoMotion still receives the original RGB. Choose geometry using observed evidence only.
3. Estimate AX=XB hand-eye using TCP xyzw camera-to-base transforms and ViPE camera-to-world transforms. Report multi-axis excitation, conditioning, physical plausibility and held-out translation/rotation/reprojection errors. Do not accept an underdetermined or implausible solution as measured extrinsics.
   Historical repair control: if ViPE-derived X fails the predeclared physical gate, retain it as rejected evidence and independently estimate X using official K, observed sensor depth, static RGB correspondences and robot TCP, with a disjoint held-out suffix. This additional independent calibration may supply branch C only after the same observed reprojection gate passes; disclose remaining excitation/registration/scale uncertainty. This decision is made before MolmoMotion or future data.
4. Compare ViPE and sensor depth on target, robot, static table/bin, and background: median absolute error, p90, scale ratio, temporal variation, and RGB/depth/difference figures. Sensor scale 0.0001 m/unit remains a hypothesis until independent observed evidence identifies it.
5. Build three controlled geometries on identical frozen 24 target IDs: A ViPE depth/K/pose; B sensor depth + ViPE K/pose; C sensor depth + official/validated K + TCP hand-eye pose. Transform all H3 points into camera_t0. Apply and record author filtering/smoothing where valid; report raw and smoothed sensitivity.
6. Choose primary geometry from observed validation and freeze that decision before future metrics. Inference H3-F30, BF16, greedy, seed 0, three complete P8 groups per geometry. Save actual processor payload, anchor, raw text and strict parser audit.
7. Independent future AllTracker reference for the frozen IDs. Future robot or evaluation-only visual camera poses are allowed only for evaluation. Static and observed constant velocity baselines; retain off-image predictions. Align nominal source 10 Hz to model 15 Hz by time.
8. Wrist_1 observed ViPE replication and TCP hand-eye comparison; compare object/world motion or rigid target geometry with uncertainty and no unverified shared material-point IDs. Side_1/side_2 sensor geometry controls with observed alignment; no exact stereo triangulation or hardware synchronization claim.
9. Per the user's correction, use the assistant's built-in image inspection (`view_image`), with no separate Hugging Face VLM. Review historical tracks, future reference, and blinded forecast overlays; save reviewed image hashes and source frame IDs, explicit per-image/per-point qualitative judgments, and uncertainty. Built-in visual review is qualitative evidence; it does not create calibrated 3D ground truth or choose geometry using future outcomes. Do not claim an externally reproducible independent VLM checkpoint.
10. Report, camera path and error plots, depth maps, moving-camera forecast videos, reproduction commands, and requirement-by-requirement completion audit. Numerical reconstruction failures and VLM disagreements must remain visible.

Observed geometry gates, fixed before ViPE results: static background median reprojection <=4 px and p90 <=10 px with >=30 correspondences across >=3 temporal pairs; at least 24 valid target tracks on all H3 frames; proper finite SE(3); depth positive and finite; target relative pair-distance variation median <=0.15. Hand-eye is usable as estimated X only with fit/test residuals disclosed, finite solution and plausible |translation|<=0.5 m; assess rotation excitation and bootstrap sensitivity separately. Failure does not authorize fabricated geometry or silently relaxing the gate. A failed branch can be run as an explicitly marked diagnostic if useful, without being chosen as validated primary.

The cameras store latest available independently threaded frames and no hardware timestamps. Cross-view agreement is approximate, with observed-only temporal-offset assessment where needed. Scale, pose, clock, registration and calibration errors limit the meaning of estimated 3D metrics.
