# Улучшение Berkeley UR5 → MolmoMotion

Цель сохранена полностью: выполнить исследования из приложенного описания на основе опубликованного эксперимента `4f11c56`, оценивая траектории прежде всего визуально. Успешное уменьшение одной метрики не означает завершение исследования.

1. Фиксированный коэффициент перемещения `1/3` вокруг собственного t0 каждой точки и независимый вариант step1→frame1: выполнены для обеих сцен, массивы, графики, MP4 сохранены. Визуальная оценка: размах меньше, остаточная ошибка направления/времени остаётся.
2. Oracle least-squares alpha и перенос cup→bottle / bottle→cup: выполнены, явно помечены как диагностика с будущими данными.
3. Скорости raw/smoothed H3 для тех же 24 точек: выполнены; трёхкратного ускорения нет.
4. CASE-AUGE: источник FOV подтверждён; реальный cup/group_00 выполнен, полный raw ответ 8×30 и GPU receipt сохранены. Дуга визуально уменьшилась. Полный 24-point run для обеих сцен поставлен после H1.
5. CASE-NOK: реальный cup/group_00 выполнен. После `1/3` прогноз визуально значительно ближе к стакану и перестал описывать широкую дугу вправо. Полный 24-point run обеих сцен поставлен после AugE. DELTA без K использует жёсткий default f=W, поэтому строгая независимая геометрия использует MoGe-2 с fov_x=None и ту же sensor Z. Геометрия обеих сцен подготовлена.
6. Kalib: официальный код и требования проверены, audit сохранён в sources/kalib_readiness.json. PnP путь требует K и TCP соответствий; имеющиеся объектные точки не являются известными TCP точками. Калибровка не запускалась; для содержательной дополнительной проверки нужны подтверждённые TCP соответствия.
7. ShareRobot↔Berkeley mapping: искать реальные sequence IDs и подтвердить выбранные сцены сравнением RGB. Номер эпизода сам по себе недостаточен. В работе.
8. H1-F32 на cup: реальный first-P8 контроль выполнен после двух геометрических пилотов. Полный строгий ответ 8×32 сохранён. Визуально большая дуга размещения начинается слишком рано; проблема не устранилась при удалении H3. Checkpoint уже был скачан в workspace; повторное скачивание не потребовалось.
9. Сохранить исходные результаты без изменения байтов, все варианты отдельно, протоколы новых реальных запусков, визуальный отчёт и ограничения. Опубликовать результаты в существующем GitHub репозитории.

Не повторять MolmoPoint, SAM2.1, K-means или AllTracker. Не выбирать заново точки, сцены, t0 или instruction. GT tracker/reference общие; будущие RGB-D не участвуют в новых геометрических входах. Не выдавать oracle alpha, центрированную камеру AugE или внутренний DELTA default за измеренную калибровку.

Дополнительная проверка строгости: CASE-NOK сохраняет прежний smoothed sensor Z, чтобы отдельно изучать эффект лучей. Эти Z ранее сглаживались с UniDepth-геометрией, поэтому для строгого no-prior-K подготовлена отдельная CASE-NOK-STRICT: raw XYZ, trust, anchors и smoothing пересчитаны из native depth и прежних 2D tracks с исключительно MoGe-лучами. Все 24 ID сохранены. На cup выбранные ID не отмечены новым outlier filter; на bottle отмечен ID 30, который сохранён ради общего набора точек и требует отдельной визуальной проверки. Требуется реальный первый P8 пилот, затем визуальное решение о полном запуске.
